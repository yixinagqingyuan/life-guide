# 本地 Markdown 检索设计

## 数据与切片

Markdown 是唯一知识正文。34 章、676 个完整条目保留作者的成本、解释、收益、证据等级、来源和备注；固定版本与校验值见 [来源说明](../knowledge-base/SOURCES.md)。

运行时读取条目，在成本、说人话、收益和备注四个字段内部生成检索窗口：每个最多 600 字符，相邻窗口重叠 100 字符，不跨字段。当前快照产生 2,776 个窗口。来源和证据标签不作为窗口正文，避免参考文献中的无关词主导召回；仍完整保留在回答上下文中。

窗口携带父条目 ID 和精确字符位置。索引和窗口只存在进程内存，后续命令重新建立；同一进程通过文件大小和修改时间检查是否需刷新缓存。索引建立时校验原文 SHA-256，不悄悄接受正文被改动的条目。

## 召回与排序

1. 用 Unicode NFKC 统一字符宽度，中文取二字和三字片段，英文与数字取词，近义表达表中的长短语补充为完整检索词。不依赖分词模型。
2. 从问题移除少量礼貌和问句词；查询原词保留较高权重。读取 [近义表达表](../knowledge-base/topics/keywords.md)，将命中的口语扩展为规范词，扩展词权重为 0.55。
3. 原查询、混合扩展查询与纯规范主题词分别执行 BM25F；没有扩展组时只执行原查询。规范词一路不包含原问题的其他字词，避免长文案中的杂词挤掉相关条目。标题、辅助关键词、通俗解释、窗口正文的字段权重分别为 4、1.5、2、1；各字段长度归一化参数分别为 0.2、0.3、0.5、0.75，词频饱和参数 k1 为 1.2。各字段先归一化并加权，再对合计词频做饱和处理。IDF 按窗口出现频次计算。
4. 每路先保留父条目的最佳窗口，使一个长条目不会因多个窗口反复投票。各路最多 80 个父条目，按 `路权重 / (60 + 名次)` 做 RRF；原查询和规范词路权重均为 1，混合扩展路权重 0.7。
5. 用原查询词与规范词加权覆盖的较大值、原查询标题覆盖、近义组前两个规范词的标题命中和优先章节做规则重排。这样不会仅因口语在原文中出现少，就抹掉规范主题的相关性。扩展时另取原查询中至少三字符、确实出现在语料标题中、且不属于规范扩展词的片段，按 IDF 加权的标题覆盖以 `1 + 0.8 × 覆盖` 加分，保留“布洛芬”等具体词，避免被“怀孕”等宽泛主题冲淡。它仍是字面匹配，不是实体识别。没有近义组且原查询覆盖低于 0.3 时，不返回该候选。无足够候选时输出 `no_match`。输出中的 `canonical_coverage` 和 `specific_title_coverage` 都是覆盖指标，不表示置信度。

这是词法检索的工程增强，规则重排没有神经网络。覆盖阈值只能减少部分无关命中；触发扩展组时仍可能召回无关候选，需要根据完整原文判断适用性。分数没有概率或事实可信度含义。

2026-10-10 的实际使用暴露了午睡表达缺漏及排序问题：原查询“午休”误召回晒太阳，“下午犯困”和含午睡的较长口语问句没有结果。只新增近义组后，午睡条目能召回，但“午休”的字面命中仍排在晒太阳上，文案全文中的杂词也会挤掉相关结果。此次补齐“午睡与午休”近义组，增加规范词独立召回并纳入覆盖重排；`test_retrieval.py` 保留七种短词、长问句和文案全文的回归案例。用例通过不表示已经具备通用语义理解。

BM25F 的字段归一化参考 [原始 BM25F 研究](https://terrierteam.dcs.gla.ac.uk/publications/IPM_he.pdf)，RRF 的名次融合参考 [原始 RRF 论文](https://cormack.uwaterloo.ca/cormacksigir09-rrf.pdf)。具体权重、字符窗口和中文规则是本知识库的实现选择。

## 上下文与引用

`passage` 是实际索引窗口的逐字片段，`start` 和 `end` 是完整原文中的 Python 字符索引，不是原始文件的字节或行号。输出片段与原文切片完全一致，不能仅凭窗口推断整条建议。

`--context` 按排名读回完整父条目，再补读条目导航中的明确交叉引用，默认最多两条。不从相似标题推造关联，不把交叉引用当成额外推荐。原文超出剩余字符预算时整条省略，并输出省略 ID；随后可以单独读取。

`--verify-citation` 校验逐字引文与该条目是否匹配，并检查正文校验值。它只检查引文存在与来源完整，不核实现行医学、法律、政策或数字，也不评判引文是否足以支持回答中的解释。

检索、读回完整条目、展示提醒是三个不同环节。Skill 读完原文核对适用条件后，默认直接展示选中条目的 `title` 原标题，不再从正文另挑一句替换；这样不会在午睡条目里只摘出“定闹钟”的成本句而遗漏午睡建议。

默认与旧版检索的 `results` 都返回 `value_rating`，供提醒只展示“性价比：极高／高／一般”中的对应分档。`--show` 的 `metadata` 也包含该字段。成本收益原值仍保留供核对，不在默认提醒中展开。

分档沿用原作者固定提交的 [COST_W 与 ratioOf()](https://github.com/eternity4719/HowToLiveBetter/blob/bb25081b423091f9e22059aab6b4ed7343a2266d/tools/lib/book.mjs#L59-L70)，说明见本地 [性价比档](../knowledge-base/UPSTREAM.md#性价比档)。金钱 `0/少/多` 权重为 `0/1/2`，时间 `少/中/多` 为 `0/1/2`，毅力 `否/些/是` 为 `0/1/2`；三项相加，收益大且成本为 0 则极高，收益大且成本不超过 2 则高，收益中且成本为 0 也为高，其余一般。缺失或未知标签返回未标注，不按零成本处理。`search_kb.value_rating()` 在读取时派生分档，不改写原条目。当前快照核对结果为极高 114、高 303、一般 259，与上游导读一致。

性价比是作者判断，只在同收益口径内可比，与证据等级及检索分数无关，也不额外参与排序。完整原文仍用于核对标签及条件，引用校验不能替代适用性判断。

## 评测与维护边界

运行 [评测脚本](../scripts/benchmark_retrieval.py) 查看 [开发样例报告](retrieval-evaluation.md)。报告同时比较原版、扩充近义表达的原版和新版，可区分词表完善与算法改动的贡献。样例参与过调整，不能当作未知问题的准确率。

纯中文二/三字片段可能错误匹配，口语映射依赖人工词表，也无法识别复杂否定、反讽和上下文省略。问题很宽时先结合用户已给出的背景缩小检索范围。需要维护新表达时修改构建脚本与生成词表，并检查原文条件、备注和无答案场景；不为好看的指标扩写知识结论。
